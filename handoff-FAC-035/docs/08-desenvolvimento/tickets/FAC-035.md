# FAC-035 — Tarefas Scrum com persistência

READY por pedido do usuário em 2026-10-09. Base: `developer` (SHA registrado na criação da worktree). Branch: `feat/fac-035-tarefas-scrum`. Risco R2 (migração de schema nova, sem alterar tabelas existentes). Sucede a demonstração local do FAC-033.

## Objetivo e escopo

Substituir a demonstração em `localStorage` do painel Tarefas por gestão ágil persistida em PostgreSQL: épicos, sprints e itens de trabalho (história, tarefa, bug, spike) com story points, responsável (agente ou humano), relator, origem (agente/manual), selo "Editado manualmente", impedimentos (bloqueio/dúvida), critérios e subtarefas marcáveis, "bloqueado por", comentários e histórico. Três visões: quadro da sprint ativa, backlog por sprint e épicos. Visual conforme `docs/09-entregas/2026/evidencias/FAC-035/03-especificacao-visual.md`.

Itens de trabalho são **planejamento**. Não substituem nem alteram `Ticket`/`Run`/outbox; nada aqui publica READY nem executa agentes.

## Critérios de aceite

1. Dado um projeto cadastrado e sessão admin, quando o operador abre Tarefas, então vê épicos, sprints e itens lidos da API, sem aviso de demonstração e sem uso de `localStorage` para dados.
2. Dado um item criado ou editado, quando a página é recarregada, então todos os campos persistem iguais.
3. Dado um item com `origin=AGENT`, quando o operador salva qualquer alteração, então `editedManually` passa a `true` e o selo mostra "Editado manualmente"; itens `MANUAL` nunca exibem selo de agente.
4. Dado um item, quando o operador registra bloqueio ou dúvida com motivo, então o card ganha borda e etiqueta da cor do impedimento, os contadores do topo atualizam e o histórico registra autor e data; ao resolver, tudo volta ao normal.
5. Dado um item com bloqueio ativo, quando alguém tenta movê-lo para Concluído, então a API responde 409 e a UI mostra "Remova o bloqueio antes de concluir".
6. Dado critérios e subtarefas todos marcados e nenhum impedimento, então a Definition of Done aparece "Atendida"; caso contrário, "Pendente". Calculada, não armazenada.
7. Dado duas abas editando o mesmo item, quando a segunda salva com `version` desatualizada, então a API responde 409 e a UI pede para recarregar sem sobrescrever.
8. Dado "bloqueado por" apontando para item de outro projeto, para si mesmo ou formando ciclo, então a API responde 400 e nada é gravado.
9. Dado responsável agente desabilitado ou de outro projeto, então a API responde 400.
10. Dado um projeto com sprint ATIVA, quando outra sprint é ativada, então a API responde 409 (no máximo uma ativa por projeto).
11. Filtros (busca, responsável, tipo, prioridade, épico, impedimento) e agrupamento por épico operam sobre os mesmos dados nas três visões; totais e pontos batem com os itens visíveis.
12. Sem sessão admin, Tarefas mostra chamada para entrar e não faz requisição.
